A11yGo — Fixture de verificación manual

Shadow DOM (#1) e iframes same-origin (#3): traversal, avisos y highlight frame/shadow-aware.

  1. Carga A11yGo sin empaquetar en chrome://extensions/ (modo desarrollador) apuntando a la raíz del repo — NO a dist/ (es una build congelada).
  2. Sirve el repo por HTTP (p. ej. npx http-server -p 8080 -c-1) y abre http://localhost:8080/test-fixtures/manual-a11y-test.html. No uses file://: Chrome trata cada URL file: como origen único y el iframe no carga.
  3. Con la extensión activa, ejecuta Validar Accesibilidad. Tras cualquier cambio, recarga con Ctrl+Shift+R (recarga dura).
  4. Verifica en el panel lateral que aparecen los problemas de cada tarjeta y que, al hacer click en cada uno, la página hace scroll y el overlay pulse se posiciona sobre el elemento correcto (incluido dentro del shadow root y del iframe).

A. Baseline (documento principal) sanity

Imagen sin alt en el documento top — confirma que el flujo básico y el highlight normal siguen funcionando.

Esperado: un resultado noAltText. Al hacer click, el overlay cae sobre la imagen naranja de arriba.

B. Shadow DOM abierto (#1) shadow

Un host con shadowRoot abierto que contiene una imagen sin alt y un campo de formulario sin etiqueta. El validador debe penetrar el shadow root.

Esperado: problemas dentro del shadow: noAltText (imagen morada) y placeholderAsLabel/missingLabel (el campo de texto), con selector interno que incluye >>>. Al hacer click, el overlay se posiciona sobre el elemento dentro del shadow root.

C. Iframe same-origin (#3) iframe

Iframe de mismo origen (archivo aparte servido desde localhost) con su propia estructura: un <h1> propio, una imagen sin alt, y — anidado — un shadow host con otra imagen sin alt (caso combinado ::iframe:: … >>>).

Esperado: (1) noAltText para la imagen azul del iframe — selector con ::iframe::. (2) noAltText para la imagen roja del shadow dentro del iframe — selector con ::iframe:: … >>>. (3) NO debe aparecer invalidHeadingOrder por el <h1> del iframe conviviendo con el de la página (evaluación por-documento). Al hacer click en cada uno, el overlay cae sobre el elemento dentro del iframe, bien posicionado.
